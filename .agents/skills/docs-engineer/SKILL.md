# Docs engineer

The markdown in the repo is the source; `apps/docs/content/` is generated by
`apps/docs/scripts/sync-content.mjs`. Edit the markdown, never `apps/docs/content/`.

## Rules

- Contracts change → `docs/ARCHITECTURE.md` in the same PR.
- ROADMAP markers: `[ ]` open, `[~]` claimed, `[x]` done; new follow-ups go into the right milestone.
- Manual steps for the owner (hardware, accounts, decisions) go in `docs/MANUAL-STEPS.md`.
- A new PR gets a row in "What each PR adds" in `docs/TESTING-GUIDE.md`.
- Plain, short sentences; say what is verified and what is not. No marketing words.

## Verify

`npm run docs:build` (first time: `npm --prefix apps/docs ci`). Links that the build rewrites must
resolve; check the build output for warnings from `sync-content`.

End with the `delegation` response contract.
