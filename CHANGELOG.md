# Changelog

Every PR adds a line under **Unreleased** (newest first) with its PR number. When the owner
merges the stack to `main`, the Unreleased block becomes a dated release.

## Unreleased

### Added
- Snapshot / video export: the **Snapshot** button opens a menu: PNG at 1×, 2× or 4× the stage (shrunk to the GPU limit and 16.7 MP for iOS Safari) on the stage's backdrop, transparent or chroma green, with or without pins; and a 360° turntable video (8 s, WebM, MP4 in browsers that only record that, hidden where `MediaRecorder` cannot record a canvas). The camera, drawing buffer and clear color are restored afterwards. (#22)
- iOS capture guidance + JPEG photos: the capture screen has a checklist (3 orbits at hub height, saddle height and top-down, ticked as Object Capture completes each pass; close-ups of fork crown, dropouts, rear derailleur and cockpit; shots per pass; reflective-paint tips, and why a turntable does not work with on-device Object Capture). Exported bundles add `photos/*.jpg` (2048 px, upright) listed as `manifest.photos`, and the web viewer uses them instead of decoding HEIC. (#14)
- WebKit E2E: the iPhone specs also run in Playwright WebKit (Safari's engine) via `npm run e2e:webkit` (local, on a Mac; CI is a roadmap item). (#16)
- Auto-publish: every push to `develop` republishes the site (`.github/workflows/pages.yml`), and each open PR from this repo gets a preview at `/bike-3d-brew/pr/<n>/` (docs + viewer), removed when the PR closes (`pr-preview.yml`), listed under "PR previews" on the home and Progress pages from `/pr/index.json`. `tools/publish-pages.sh` gains `--pr`, `--title` and `--remove-pr`, only replaces its own part of gh-pages (the main site keeps `/pr/`), and retries on the latest gh-pages when another run pushed first. (#15)
- Performance: the viewer renders on demand (an idle stage draws 0 frames, the loop pauses in hidden tabs), redraws the shadow map only when the scene changes, caps the pixel ratio per device (`?quality=low|high`), welds USDZ meshes into indexed geometry (2.9M → 0.49M vertices on a 1M-triangle capture), builds a BVH in a worker so picking and pin occlusion cost ~0.05 ms instead of ~200 ms, and updates 50+ pins with budgeted occlusion and transform-only writes. GLBs with Meshopt, Draco or KTX2 load with lazily fetched, self-hosted decoders; `tools/optimize-glb.mjs` makes phone-friendly GLBs; `tools/bench/bench.mjs` measures it all. See `docs/PERFORMANCE.md`. (#12)
- Photos & video → 3D research (`docs/RECONSTRUCTION.md`): reconstruction options for bikes, recommendation (Object Capture on macOS by default, COLMAP + OpenMVS as fallback, splats later), photo and video capture protocols, owner decisions; new ROADMAP Milestone 1.5. (#11)
- Share with customers: read-only `?scene=…&view=present` link served by a standalone presenter (`present/BikePresenter.ts`, no editing code, container-scoped), Share button (share sheet / clipboard / visible link), `bike-share/1` package export + `tools/publish-scene.mjs`, published demo at `scenes/demo/`. Present mode: leader lines, progress dots, swipe, auto-play (`?kiosk=1`), phone bottom sheet; markdown-lite comment bodies (DOM-only renderer); drag / ↑↓ comment reordering. (#8)
- Crop box: Edit → Model → Crop clips everything outside an axis-aligned box (model-root space, saved as optional `crop` in `bike-scene/1`) with renderer clipping planes; drag the face handles (mouse or touch) or type the corners; "Fit to bike" removes the floor slab and background clusters. Cropped-away geometry can't take comments, and comments outside the box are hidden. Area-mode captures get a suggested box and a hint. (#10)
- Auto-orient captures: a scanned bike is stood upright facing +X (PCA + side-view ground line, bike-shaped sign heuristics) on first load, with a toast; Edit → Model has Auto-orient, rotate ±90° per axis, flip, turn 180°, scale, real length in cm, 1 cm nudges, on-ground, undo and reset. Comments stay attached. `tools/fixtures/make-bike-capture.mjs` generates tilted test bundles. (#9)
- Test system: Playwright E2E suite (`npm run e2e`, desktop + iPhone viewport, sharded CI job) over the production build, covering every viewer flow including stored captures, photo close-ups and binary USDC; synthetic capture-bundle fixtures (`tools/fixtures/make-capture-bundle.mjs`, rendered-photo bundle via `render-photos.mjs`); unit coverage with ratcheting thresholds (`npm run test:coverage`, ~99.8% lines) incl. zip64 parsing, OPFS/IndexedDB backends and the photo UI; `docs/TESTING.md`. UI decisions moved into tested `scene/helpers.ts`; `?e2e` test hook. Fixed: a tap right after an instant (reduced-motion) fly-to missed the model. (#7)
- Photo close-ups: for the active area, the active comment and each Present step, a filmstrip of the capture photos that best show it (ranked from `poses.json`), with a full-screen viewer (swipe, arrows, pinch/zoom). Photos are read lazily from the zip, HEIC is decoded natively or by a lazily loaded WASM worker, and thumbnails are kept in the capture cache. (#6)
- Captures survive reloads: opened `*.bikecapture.zip` bundles are kept in browser storage (OPFS, IndexedDB fallback, LRU under a quota-aware budget) and reopen automatically; "Open…" lists stored captures with size and a forget button. Synthetic fixture generator in `tools/fixtures/`. (#5)
- Docs & progress site (Fumadocs, `apps/docs`) generated from the repo's markdown: home dashboard with roadmap progress per milestone, latest changes and build commit; "How to test" guide; offline search. `tools/publish-pages.sh` publishes it with the viewer (under `/app/`) and a synthetic test bundle to the `gh-pages` branch; `tools/make-test-bundle.mjs` writes a synthetic `*.bikecapture.zip`. The Actions-based `pages.yml` deploy is removed. (#4)
- USDZ robustness: Object Capture USDZ (binary USDC) loads with textures; fixes three.js r186 crate decoding of inline vectors/halves/negative ints, ~10× faster mesh build for large captures, lazy-loaded USD code, clear fallback to `tools/usdz-to-glb.py`. Synthetic fixture generator `tools/fixtures/make-usdc.py`. (#3)
- Capture bundle import: drop an iPhone `*.bikecapture.zip` on the viewer; it is unzipped in the browser, the model loads and the scene is named from the manifest. Re-dropping a bundle restores its comments. (#2)
- Foundation: three.js viewer/editor with areas, pinned sales comments, present mode, background modes, `bike-scene/1` format; iOS Object Capture app skeleton; CI. (#1)
