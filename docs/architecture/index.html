Architecture

Why Object Capture instead of Wes Bos' room pipeline

wesbos/3d-model-anything records RoomPlan + LiDAR mesh + posed photos, then an AI agent rebuilds the room in three.js. A bike is one object with thin tubes, spokes and cables, so we use Apple's Object Capture: guided orbits, automatic object masking (the background is removed during reconstruction; no green screen needed) and a textured USDZ. We keep Wes's key idea of posed photos: poses.json tells us where each photo was taken, so the viewer can show real close-up photos for an area (e.g. the fork crown) next to the 3D view.

Fallbacks when Object Capture struggles with a bike (thin spokes are the classic failure): area mode + a crop box, or a gaussian splat (Scaniverse/Polycam/Luma) for photoreal paint. The green background mode exists for compositing snapshots/videos in other tools.

PathContent

images/Object Capture HEIC photos
record.jsonapp-internal record

Importing in the browser (apps/web/src/scene/capture.ts): dropping a *.bikecapture.zip unzips it in memory with fflate; nothing is uploaded. The iOS exporter zips its staging folder (NSFileCoordinator .forUploading), so files usually sit under one top-level directory: the shallowest manifest.json defines the bundle root and __MACOSX/ / ._* entries are ignored. Only manifest.json, the model and poses.json are decompressed (size-capped); images are just listed. If manifest.model is missing, a glb/gltf/usdz/ply next to the manifest is used (GLB first, e.g. after tools/usdz-to-glb.py). A broken poses.json is a warning, not an error.

The resulting scene gets a stable id (capture-<name>-<createdAt digits>) so dropping the same bundle again restores its saved areas and comments, and a model URL bundle:<zip name>/<path>, which is never fetched: after a reload the viewer asks for that zip to be dropped again.

bike-scene/1 (viewer JSON, *.bike.json)

See apps/web/src/scene/schema.ts. A scene references its model by URL (relative to the scene file), lists hotspots (named camera views: the zoomable areas) and annotations (surface point + normal, title, body, kind feature|spec|upgrade|note, optional price and area). All coordinates are in model-root space.

Open questions (verify on device)

  • Does PhotogrammetrySession.Poses return camera→model transforms in the same frame as the USDZ? (Assumed; validate by projecting a pin into the matching photo.)
  • Does three.js USDZLoader read Object Capture USDZ (binary USDC)? Otherwise convert to GLB.
  • Bike size vs. Object Capture's bounding box limits: area mode is the fallback.
