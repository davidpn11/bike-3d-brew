Milestone 2: Real captures into the viewer

8/17 done · 9 open

  • Done

    Capture bundle import

    Drop *.bikecapture.zip on the viewer, unzip in the browser (fflate), load model.usdz, read manifest.json and poses.json, name the scene from the manifest. Unit-test the bundle parser with a synthetic zip.

  • Done

    Keep captures across reloads

    Cache the unzipped model of the last opened bundles in IndexedDB/OPFS (best effort, quota-aware) so a reload reopens a capture scene without re-dropping the .bikecapture.zip.

  • Open

    Capture cache on real Safari / iOS

    Verify OPFS createWritable() vs. the IndexedDB fallback, quota numbers and persist() behavior on iPhone Safari and a home-screen web app; tune the 500 MB budget for phones.

  • Open

    Cache large models without a main-thread copy

    Write models to OPFS from a worker (createSyncAccessHandle) or straight from the dropped File stream, so a 300 MB capture does not briefly double memory on phones.

  • Done

    USDZ robustness

    Three r186 reads binary USDC; apps/web/src/viewer/usd/ fixes its inline-value decoding, speeds up large meshes ~10×, waits for packed textures and falls back to a tools/usdz-to-glb.py hint. Synthetic Object-Capture-like fixtures from tools/fixtures/make-usdc.py.

  • Open

    Verify a real Object Capture USDZ

    Load a real model.usdz (owner's iPhone, see docs/MANUAL-STEPS.md), compare against Quick Look; turn anything off into a fixture-based test (synthetic re-creation, never the capture itself).

  • Done

    Weld USDZ meshes

    Three expands face-varying meshes to 3 vertices per triangle (~3M vertices for a 1M-triangle capture); identical corners are merged into an indexed geometry (hash-based, typed arrays, O(n)): 2.9M → 0.49M vertices, 89 → 26 MB of geometry on the 1M-triangle fixture. Decimation stays offline (tools/optimize-glb.mjs --simplify). See docs/PERFORMANCE.md.

  • Done

    Auto-orient captures

    Detect the ground plane / longest horizontal axis so a scanned bike stands upright facing +X; expose rotate/scale/offset controls in Edit mode (writes model.rotation/scale/offset).

  • Open

    Auto-orient on real scans

    Check the up/front heuristics (scene/orient.ts) against real Object Capture bikes (flat bars, kids' bikes, e-bikes with a battery, kickstands); tune the vote weights and add the cases as generated test fixtures.

  • Done

    Crop box for area-mode / splat captures

    Draggable box in Edit mode that clips everything outside (clipping planes), saved in the scene, so area-mode scans get a clean background.

  • Open

    Crop polish

    A rotatable (oriented) crop box for scans whose model-root axes are tilted; a floor-height handle that also re-grounds; show how many comments the crop hides.

  • Done

    Photo close-ups per area

    Use poses.json to find the capture photos that look most directly at each area target (angle + distance score) and show them as a filmstrip under the area; tap to open full screen. HEIC → JPEG conversion at export time on iOS if browsers can't decode HEIC.

  • Done

    iOS JPEG photo export

    Write images/*.jpg (or a photos/ folder of 2048 px JPEGs) next to the HEICs in the bundle so Chrome/Firefox skip the 2 MB WASM HEIC decoder and decoding is instant; the web side already prefers whatever decodes natively. Done: photos/*.jpg (2048 px, upright) + manifest.photos; the web reader uses them when present.

  • Open

    Drop the WASM HEIC decoder

    Once every exported bundle has photos/, remove libheif-js (LGPL) or keep it only for old bundles; also check the exported zip size growth (~0.5 MB per photo) on a real capture.

  • Open

    Validate close-ups on a real capture

    Confirm Object Capture poses share the USDZ frame and the 65° landscape intrinsics assumption (portrait captures, EXIF rotation); read real intrinsics if the iOS app can export them.

  • Open

    Occlusion-aware close-ups

    Raycast from each candidate camera to the target against the loaded mesh and drop photos where the bike hides it.

  • Open

    Pin favourite close-ups

    Let staff star photos for an area (the schema already has Hotspot.photos) and show starred ones first, also in shared links.
